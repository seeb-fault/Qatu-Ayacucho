La documentación de arquitectura describe el sistema objetivo, no una declaración de que todos los módulos ya estén implementados. Las evidencias y hashes de los quickstarts originales son históricos; no se presentan como ejecuciones nuevas ni se reemplazan sus resultados por supuestos. Los nuevos checks de GitHub Actions se deben consultar por rama y pull request.

Los textos históricos se preservan, incluidos sus formatos de salto de línea. Se organizan en commits documentales individuales y grupos de activos relacionados. Los archivos `.env`, adjuntos de identidad, dependencias, bases locales y directorios generados no se exportan: solo se usan archivos previamente versionados.

004–008 tienen especificaciones previas, pero ninguna implementación nueva en esta reconstrucción. El manifiesto `.github/entrega.json` distingue base documental, 001, 002 y 003; cada aplicación se valida solo después de incorporarse. Las decisiones pendientes de seguridad, conservación, mapas y operación siguen siendo las indicadas en las especificaciones.
